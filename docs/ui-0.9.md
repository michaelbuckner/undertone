**Undertone / studio interface / v0.9.0**

The selected direction is a dark studio instrument: charcoal surfaces, warm ivory text, amber emphasis and restrained mint state indicators. The aim is an instrument you can read while holding a bass, with a recognizable identity that can later translate to a physical panel.

The implementation introduces an original interval mark, a consistent sans-serif hierarchy, grouped panels, custom native buttons, switches, menus, faders and rotary controls. The main Play action is prominent; Generate, Panic and capture actions have distinct emphasis. Performance and Sound share the same visual language and musical state. This is a native JUCE interface, with vector drawing rather than bitmap skins.

Chord cards display the actual voiced notes alongside chord names. A lock outline and icon distinguish frozen voicings; active playback has an amber border and a progress line derived from the current chord's timing. Pending choices retain their preview. Eight-chord phrases keep readable actions in two rows. Scene recall buttons indicate the selected scene; recording gains a red state and a running duration. The output meter reflects engine peak amplitude, not a decorative animation or a calibrated loudness measurement.

Keyboard focus remains visible, editable parameter values and accessible control names are retained, and delayed tooltips explain less obvious controls. Small windows retain scrolling. The full Performance surface remains 1124×850 in the standard Windows smoke capture; the Sound surface remains 1124×1502. No synthesis, generation, MIDI export or session-format changes are part of this pass. Existing schema 8 sessions remain compatible.

**Before selling it.** This establishes a visual direction, not commercial release readiness. The next product-design work should focus on a preset/session browser with clear saved-versus-edited state, first-run output setup, and a more compact Sound editor with focused sections. Those need workflow design, not just decoration. Validate font size and contrast from a real playing position, keyboard-only operation, screen readers, multiple display scales and smaller laptops. Signing, installation, Mac execution, physical device qualification and licensing review remain separate release work. No installer, entitlement screen or purchase flow was added.

**Local verification.** Performance and Sound were rendered from the same stopped state, including an eight-chord fixture. Live Windows checks cover custom control interaction and state changes; the existing engine/session test suite remains the regression gate. See `build/verification-0.9.0.txt` and `build/package-audit-0.9.0.txt` in the development workspace for test and delivery evidence. Source comparison against v0.8 confirms that the musical core, session serialization and MIDI export are unchanged.
